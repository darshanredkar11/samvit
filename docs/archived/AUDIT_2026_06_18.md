## 2. ARCHITECTURE ASSESSMENT

### Strengths

✅ **Clean separation of concerns**
- Admin system is isolated in `admin.py` and doesn't pollute core tools
- Rate limiting, logging, and compression are standalone modules
- Migrations are versioned and idempotent

✅ **Security by design**
- Token hashing: SHA-256 for fast lookup, bcrypt for verification (Defense in Depth)
- Authorization header never logged (Decision #10 enforced)
- Rate limiting with graceful bypass paths for health checks
- RBAC with four roles (agent, operator, auditor, admin)
- Audit log for every admin mutation

✅ **Operational readiness**
- Structured JSON logging with configurable format
- Health/ready endpoints differentiate liveness from readiness
- Cleanup task auto-cancels overdue pending tasks
- Database retry logic for transient errors
- Graceful degradation (embeddings optional, headroom optional)

✅ **Database design**
- Migrations use idempotent `CREATE TABLE IF NOT EXISTS`
- Token SHA-256 indexed for O(1) lookup
- Audit log indexed by created_at for time-range queries
- All admin tables use JSONB for flexible attributes

✅ **Test coverage**
- Admin RBAC role enforcement
- Auth hashing determinism
- Rate limit per-agent isolation and expiry
- Database retry logic for transient errors
- Pagination boundary conditions
- Compression wrapper behavior

### Observations

⚠️ **Potential concerns (low-risk)**

1. **Admin UI delivery**
   - Admin SPA is a separate build (Vite) deployed alongside FastAPI
   - Served as static files from `/admin/*` route
   - No separate origin for CSP isolation (could be improved for defense-in-depth, but acceptable for local/trusted networks)

2. **Rate limiting scope**
   - In-memory storage only; lost on restart
   - OK for single-instance deployments; multi-instance needs Redis or pg backend
   - No documented guidance on this trade-off

3. **Compression (headroom) optional**
   - Gracefully disabled if library not installed
   - Good design, but no warning in logs if intended but missing

## 3. SECURITY REVIEW

### Token Authentication ✅ Excellent

```python
# SHA-256 for fast index lookup, bcrypt for verification
sha256 = _token_sha256(token)
row = await conn.fetchrow(
    "SELECT ... FROM agents WHERE token_hash_sha256 = $1",
    sha256,
)
if await verify_token_hash(token, row["token_hash"]):
    return dict(row)
```

- **Strength:** Two-factor lookup prevents all timing attacks (constant-time index + bcrypt)
- **Strength:** Bcrypt with 12 rounds offers resistance to GPU/ASIC cracking
- **Strength:** Token generation via `secrets.token_urlsafe(48)` → 384-bit entropy
- **No vulnerabilities identified**

### Authorization ✅ Sound

```python
def _require_role(agent: dict, *allowed: str) -> None:
    role = agent.get("role", "agent")
    if role not in allowed:
        raise PermissionError(f"Role '{role}' is not allowed...")
```

- Role is loaded from DB (immutable during request), not from token/header
- Checks on every admin endpoint
- Audit logged for all mutations
- **No privilege escalation paths identified**

### Audit Logging ✅ Complete

All admin mutations logged to `admin_audit_log`:
- Agent registration, suspension, role changes, token rotation
- Task force-release, cancellation
- Settings mutations
- Admin action: who, when, what, target

**Recommendation:** Integrate audit log into monitoring/SIEM for production deployments.

### Input Validation ✅ Present

- Handle validation: `^[a-z0-9_-]{1,64}$`
- Provider non-empty check
- Task UUID, memory namespace validation
- No SQL injection (parameterized queries throughout)
- No XSS in admin UI (React auto-escapes, no `dangerouslySetInnerHTML` found)

**Issue Found (Low):** No rate limit on `/v1/agents/register` — theoretically allows bruteforce agent name enumeration or DoS via unlimited registration. **Mitigation:** bypass path is intentional for first-use signup, but recommend adding `SAMVIT_ALLOW_PUBLIC_REGISTER=false` env var in docs.

### Data Privacy ✅ Well-Protected

- Authorization header redacted at middleware level
- No plaintext tokens in logs
- Token hashing ensures even DB leak doesn't expose tokens
- Suspension prevents token reuse even if extracted

## 6. IDENTIFIED ISSUES

### Issue #1: Admin Secret in Environment (Medium)

**Location:** `samvit/auth.py:164–172`

```python
async def admin_reset_token(handle: str, admin_secret: str) -> str:
    import os
    expected = os.environ.get("SAMVIT_ADMIN_SECRET", "")
    if not expected or not hmac.compare_digest(admin_secret, expected):
        raise PermissionError("Invalid admin secret")
```

**Problem:** If `SAMVIT_ADMIN_SECRET` is not set, any caller can reset any token (comparing empty string to empty string is a match).

**Recommendation:** Require explicit configuration or block the endpoint:
```python
async def admin_reset_token(handle: str, admin_secret: str) -> str:
    expected = os.environ.get("SAMVIT_ADMIN_SECRET", "")
    if not expected:
        raise PermissionError("SAMVIT_ADMIN_SECRET is not configured")
    if not hmac.compare_digest(admin_secret, expected):
        raise PermissionError("Invalid admin secret")
```

**Impact:** Low — endpoint requires bearer token auth first, so attacker needs valid agent token. But should still be fixed.
