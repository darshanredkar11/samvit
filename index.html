The two gaps in production AI coding

Your agents are isolated and expensive.

Most teams face two problems: agents can't coordinate across sessions, and every token they read costs money. Solving only one leaves you with a fragile or expensive pipeline.

GAP 1 — Coordination

Agents have no shared memory or task ownership.

Agent A learns your auth flow. Agent B repeats the same investigation tomorrow. Two agents claim the same issue because neither sees ownership. Humans copy notes between terminals. Samvit solves this: one MCP server for shared memory, atomic task claims (FOR UPDATE SKIP LOCKED), and durable messaging — PostgreSQL-backed, provider-agnostic.

GAP 2 — Token Cost

Server responses contain 60–95% redundant data.

Every recall returns memory snippets. Every search_docs returns chunked text. Every explore_code returns symbol metadata. All of it gets sent to the LLM — and you pay per token. Headroom runs inside Samvit and compresses these responses using SmartCrusher (JSON), CodeCompressor (AST), and CacheAligner (prefix stabilization). No per-machine install, no config, no accuracy loss.

For engineering teams

What the combined server delivers.

01

Shared persistent memory

Any agent on any machine can remember a decision and any other agent can recall it — by semantic similarity or exact key. No more context resets between sessions. Headroom compresses recall results by 92%.

02

Collision-free task ownership

claim atomically locks a task via FOR UPDATE SKIP LOCKED. Two agents never receive the same work. renew extends leases; done records structured results. Task descriptions compressed by 70%+.

03

Durable agent messaging

say sends directed or broadcast messages with topic routing. read consumes with mark-as-read tracking across a join table. Messages survive agent restarts. Message bodies compressed by 60%+.

04

RAG and code intelligence

ingest documents (PDF, MD, TXT) and search_docs by semantic similarity. index_code builds a graph of symbols (Python AST, JS/Go/Rust/Java regex); explore_code, who_calls, graph_symbol answer architecture questions. RAG chunks compressed by 92%.

05

Reversible compression (CCR)

Headroom's Compress-Cache-Retrieve stores originals in a local cache with TTL. If the LLM needs more detail, it calls headroom_retrieve to get the full original. Nothing is permanently lost — compression is always reversible.

06

Ethical guardrails

Samvit's guard module scans every memory, message, and document for credentials, PII, and live data — configurable to redact, block, warn, or pass through. Every violation is logged and auditable in guard_violations.

5-minute guide

Samvit is running. Now what?

From zero to a multi-agent team sharing memory, tasks, and messages — with built-in compression.

Start the server

Clone, configure, and start Samvit. Headroom is included — no separate install.

git clone https://github.com/darshanredkar11/samvit
cd samvit
cp .env.example .env
docker compose up -d
curl http://localhost:8765/health
# → {"status":"ok"}

Register your agent

Each teammate gets a unique token. Shown once — save it.

curl -X POST http://localhost:8765/v1/agents/register \
  -H "Content-Type: application/json" \
  -d '{"handle": "alice", "admin_secret": "change-me-in-production"}'
# → {"handle":"alice","token":"samvit_abc123..."}

Connect your AI tool

Claude Code, Codex CLI, Cursor — any MCP client.

# Claude Code
claude mcp add --transport http samvit \
  http://TEAM_SERVER:8765/mcp \
  --header "Authorization: Bearer samvit_abc123..."

# Codex CLI
codex mcp add --transport http samvit \
  http://TEAM_SERVER:8765/mcp \
  --header "Authorization: Bearer samvit_abc123..."

Store and find knowledge

Tell your agent to store decisions. Any agent retrieves them by meaning — Headroom compresses the results.

# In your agent's chat:
"Remember: the auth service runs on port 3001
 and uses JWT with RS256."

# Later, in any other agent:
"What port does the auth service use?"
# Agent auto-recalls. Server compresses response 92%.

Create and claim tasks

Atomic claim — two agents never get the same task.

# Agent A creates a task:
"Create a task to fix the login timeout bug,
 priority 3, tag 'backend'."

# Agent B claims it (only one gets it):
"Claim the next backend task."

"Mark it done with result
 'Fixed: increased timeout to 30s'."

Send messages across sessions

Durable messages survive restarts. Broadcast or direct.

# Agent A broadcasts:
"Say 'CI pipeline is green' with topic 'build-status'."

# Agent B reads (with Headroom compression):
"Read messages with topic 'build-status'."
# → "CI pipeline is green"

Inside the server

How Headroom compresses responses.

All three algorithms run automatically when SAMVIT_HEADROOM_ENABLED=true (default: on). No agent-side config needed.

SmartCrusher

What it does: Analyzes JSON arrays in responses (recall results, document chunks, code search), detects statistical patterns, keeps important items (errors, anomalies, change points) and compresses repetitive data.

→ 70-95% reduction on structured data

CodeCompressor

What it does: AST-aware compression for code symbols returned by explore_code, who_calls, and graph_symbol. Strips redundant tokens while preserving structure and signatures.

→ 60-85% reduction on code metadata

CacheAligner

What it does: Stabilizes response prefixes so LLM provider KV caches (Anthropic, OpenAI, Google) actually hit. Dynamic content (timestamps, IDs) is extracted to the end of the response.

→ 50-90% additional cache savings

CCR
CCR: Compress-Cache-Retrieve — nothing is permanently lost
When SmartCrusher compresses a response, the full original is cached in an in-memory store with a TTL (default 5 minutes). Headroom injects a retrieval marker in the compressed response. If the LLM needs the original data, it calls headroom_retrieve via MCP — an instant lookup, not a re-query.
Questions

For CTOs, architects, and engineers.

How is this different from LangGraph / CrewAI?

Those frameworks define how agents execute (DAGs, loops, sub-agents). Samvit provides the shared state those agents read and write — memory, tasks, messages — across sessions and machines. They are complementary: LangGraph can use Samvit as its persistence layer.

Does compression change my LLM's answers?

No. Headroom benchmarks show ±0% accuracy delta on GSM8K (math), SQuAD v2 (QA), and BFCL (tool use). Compression is statistical and structural — it removes redundancy, not meaning. CCR ensures nothing is permanently lost.

Do developers need to install anything on their machines?

No. Headroom runs inside the Samvit server as a Python library. Developers only install an MCP client (Claude Code, Codex CLI) and point it at the Samvit server. Compression happens server-side, transparently. Zero per-machine setup.

How do we secure Samvit in production?

Do not expose it to the public internet. Run behind a TLS-terminating reverse proxy (Caddy, nginx). Use strong SAMVIT_ADMIN_SECRET. Each agent gets its own bcrypt-hashed token. The ethical guard scans for credentials and PII. PostgreSQL is the single source of truth.

What infrastructure do I need?

One machine with Docker. PostgreSQL 16 (pgvector) + optional Redpanda. Minimum: 2 CPU cores, 4 GB RAM. Headroom's models add ~200MB to the container. No per-machine agents, no sidecars, no per-developer installs.

Can different agent types share the same server?

Yes. Claude Code, Codex CLI, Antigravity, Cursor, and Hermes all connect via MCP to the same Samvit server. Each gets its own token. All share the same memory pool, task queue, and message bus. Headroom compresses responses for all of them equally.

What is on the roadmap?

Workspace isolation, file-intent conflict detection, A2A compatibility, batch operations, WebSocket real-time events, richer task workflows, and deeper Headroom integration (proxy mode sidecar for agent-to-LLM compression).
