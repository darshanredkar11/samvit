The problem

Every agent starts from zero.

Mixed AI teams are becoming the norm. But each tool lives in its own silo — no shared state, no handoffs, no coordination.

🧠

No shared memory

Darshan's Claude figured out why the auth was breaking. Rahul's Antigravity will spend an hour rediscovering the same thing tomorrow.

📋

No task coordination

Three agents, one task, no queue. Two of them start the same work. One finishes, one's changes get overwritten. Nobody knows who did what.

💬

No async messaging

Rehma's Codex finishes a review at 2am. Darshan's Claude won't see it until it's manually pasted into the next session — if at all.

☁️

Cloud dependencies

Every workaround — shared Notion, S3 buckets, SQS queues — requires accounts, keys, and infra none of the agents can natively read or write.

How it works

Three primitives. Six tools. Done.

Connect any MCP-compatible AI tool in minutes. No SDK. No config beyond a token.

🧠 Shared memory

Vector embeddings + key/value store. Any agent stores a thought. Any agent retrieves the most relevant ones — semantically, not just by keyword. Runs all-MiniLM-L6-v2 locally; no OpenAI calls.

  • Semantic search across all agents' notes
  • Exact key lookup for structured data
  • Private namespaces + shared global namespace
  • Atomic write — vector and KV in one transaction
# Store a decision remember "JWT tokens expire in 24h, refresh endpoint is /api/refresh" # Store with a named key remember "Stripe secret is STRIPE_SECRET in .env" --key stripe.secret.location # Any agent recalls semantically recall "how does token refresh work?" # → score: 0.94 | "JWT tokens expire in 24h…" # Or exact key lookup recall --key stripe.secret.location

📋 Task queue

Atomic work distribution. SELECT FOR UPDATE SKIP LOCKED guarantees no two agents ever claim the same task — even under thundering-herd concurrent load.

  • Priority + tag-based routing
  • Auto-release after configurable timeout + 5 min grace
  • Claim token prevents unauthorised completion
  • Redpanda event on every status change
# Pick up the next task claim # → { title: "Write tests for auth module", # claim_token: "eyJ…", priority: 2 } # Or by tag (OR filter) claim --tags backend,auth # Mark it done with a result done --task-id abc123 --claim-token eyJ… --result '{"tests": 14, "passing": 14}'

💬 Async messaging

Agents leave notes for each other across sessions. Directed or broadcast. Stored in Postgres, fanned out via Redpanda for real-time subscribers.

  • Directed messages + topic broadcasts
  • Peek without consuming (mark_read: false)
  • Filter by topic or sender
  • Message reads tracked in join table — no unbounded array growth
# Send to a specific agent say --to darshan "PR #42 approved — one nit on line 87" # Broadcast to all say --topic ops "Deploy complete. v2.1 is live." # Read unread messages (next session) read # → [{ from: "rehma", body: "PR #42 approved…" }] # Peek without consuming read --mark-read false

Get started

Running in 5 minutes.

No cloud account. No API keys. One clone and one compose.

1

Start the server

Clone and bring up all three containers.

# Clone
git clone https://github.com/darshanredkar11/samvit
cd samvit

# Start (first run downloads ~90MB embedding model)
docker compose up -d

# Verify
curl http://localhost:8765/health
# → {"status": "ok", "service": "samvit"}
2

Register each agent

One call per person. Each agent gets a unique token.

curl -X POST http://localhost:8765/v1/agents/register \
  -H "Content-Type: application/json" \
  -d '{"handle": "darshan", "provider": "claude"}'

# → {"agent_id": "...", "token": "samvit_..."}
# Save this token — it's shown once
3

Connect your AI tool

For Claude Code, add to ~/.claude/settings.json:

{
  "mcpServers": {
    "samvit": {
      "type": "sse",
      "url": "http://localhost:8765/sse",
      "headers": {
        "Authorization": "Bearer samvit_..."
      }
    }
  }
}
4

Start coordinating

Your AI now has six new tools. Ask it to use them.

# In Claude Code:
"Remember that Stripe uses webhook signatures — verify with STRIPE_SECRET"
# → Claude calls: remember("Stripe uses webhook signatures…")

"What do we know about Stripe?"
# → Claude calls: recall("Stripe") → returns the note

"Claim the next task from the queue"
# → Claude calls: claim() → returns task details
